## Alcance autorizado

- **Objetivo y modalidad:** Implementar la infraestructura base del servidor, motor de base de datos SQLite persistente local, esquema relacional inicial, autenticación de sesiones y servicio de auditoría append-only (`MUST`).
- **Incluye:**
  - Inicialización del proyecto Node.js (`package.json`, Express, better-sqlite3 / sqlite3).
  - Migración inicial de tablas: `users`, `auth_sessions`, `audit_log`, `ai_config`.
  - Hashing seguro con `bcrypt` para credenciales de `users`.
  - Manejo de sesiones en servidor (`auth_sessions`) con cookies seguras `HttpOnly` y expiración (24h).
  - Middleware de autenticación y autorización por roles (`ADMIN`, `OPERATOR`).
  - Endpoints de autenticación: `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`.
  - Servicio de `audit_log` append-only (sin operaciones de edición ni borrado).
  - Semilla inicial de usuarios sintéticos (`admin` y `operador_demo`).
- **Excluye:** Integración externa con Gemini API (TP-02), vistas de triage (TP-03), despliegue cloud.
- **Autorizado por/fecha/mensaje:** Pendiente autorización formal del Sponsor para implementación.
- **La autorización expira si cambia el alcance:** `sí`

## Trazabilidad y protección

- **Decisiones Solution Design aplicables:** `DEC-01` (Stack Node.js), `DEC-02` (SQLite Persistente), `DEC-05` (Auth y Sesiones), `DEC-08` (Auditoría Append-Only), `DEC-09` (Secretos en `.env`).
- **Criterios de aceptación:**
  - La base de datos SQLite se crea en `data/noos_sales_flow.db` y persiste usuarios y sesiones tras reiniciar el servidor.
  - El login emite una cookie `HttpOnly` válida y `GET /api/auth/me` retorna la identidad del usuario activo.
  - El intento de modificar o eliminar un registro de `audit_log` es rechazado o no existe en la API.
- **Protected baseline:** Preservar la estructura metodológica AAGM en `.aagm/` y `docs/`.
- **Impact Analysis:** Definido en `IA-CHG-001.md`.
- **Dependencias:** Ninguna (primer Task Packet).
