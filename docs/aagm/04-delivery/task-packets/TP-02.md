## Alcance autorizado

- **Objetivo y modalidad:** Implementar la captura de solicitudes comerciales, control de idempotencia y cliente de integración con Google Gemini API (`gemini-2.5-flash`) mediante Structured Outputs y validación semántica (`MUST`).
- **Incluye:**
  - Migración de tablas: `leads`, `lead_extractions`, `lead_evidence`.
  - Endpoint `POST /api/leads/analyze` y `POST /api/leads`.
  - Control de idempotencia con `idempotency_key` (detección de reintentos con replay 200 y detección de posibles duplicados con flag `is_possible_duplicate`).
  - Módulo cliente para Google Gemini API configurado con modelo `gemini-2.5-flash` desde `ai_config` o `.env`.
  - Validación semántica de esquema JSON y verificación de subcadenas para confirmar que las citas de evidencia existen en el texto original.
  - Registro de niveles de certeza (`HIGH`, `MEDIUM`, `LOW`, `NOT_FOUND`) y soporte de campos nulos.
  - Manejo de reintentos y captura de errores en `lead_extractions`.
- **Excluye:** Interfaz visual compleja de triage (TP-03), gestión de próximas acciones (TP-04).
- **Autorizado por/fecha/mensaje:** Pendiente de autorización formal del Sponsor.
- **La autorización expira si cambia el alcance:** `sí`

## Trazabilidad y protección

- **Decisiones Solution Design aplicables:** `DEC-03` (Modelo Gemini configurable), `DEC-04` (Semántica de Structured Outputs), `DEC-06` (Idempotencia y Duplicados).
- **Criterios de aceptación:**
  - Un reintento con la misma `idempotency_key` no invoca a la IA y retorna el registro previo.
  - La extracción con IA descompone campos y citas de evidencia válidas.
  - Un fallo de cuota o timeout de la API se captura registrando el error sin bloquear el servidor.
- **Protected baseline:** Preservar autenticación y persistencia establecidas en TP-01.
- **Dependencias:** `TP-01`.

## Ambiente y validación

- **Ambiente lógico / target físico:** DEV / `http://localhost:3000` (macOS local)
- **Checks empíricos requeridos:**
  1. Prueba de extracción de solicitud con IA real o mock sintético verificado.
  2. Prueba de reintento idempotente con headers HTTP correspondientes.
  3. Verificación de citas de evidencia en base de datos SQLite.
