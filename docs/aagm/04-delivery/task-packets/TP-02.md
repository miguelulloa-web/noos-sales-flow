## Alcance autorizado

- **Objetivo y modalidad:** Implementar la captura de solicitudes comerciales en texto libre, control de idempotencia y cliente de integración con Google Gemini API (`gemini-3.6-flash`) mediante Structured Outputs y validación semántica de citas de evidencia (`MUST`).
- **Incluye:**
  - Migración de tablas: `leads`, `lead_extractions`, `lead_evidence`.
  - Endpoints: `POST /api/leads/analyze` y `POST /api/leads`.
  - Control de idempotencia con `idempotency_key` (UUID o hash):
    - Detección de reintentos exactos (HTTP 200 con payload existente y header `X-Idempotent-Replay: true`, sin re-invocar la IA ni duplicar datos).
    - Detección de posibles duplicados (coincidencia de remitente o hash de texto fuera de ventana), marcando `is_possible_duplicate = 1` y enlazando `duplicate_of_lead_id` sin fusionar automáticamente.
  - Módulo cliente para Google Gemini API configurado con modelo `gemini-3.6-flash` desde `ai_config` o `.env` (sin usar alias `latest`).
  - Validación semántica de esquema JSON de la IA y verificación de subcadenas para confirmar que cada cita de evidencia textual existe literalmente en el `raw_text` original.
  - Admisión de campos nulos/ausentes sin inventar datos (ej. empresa ausente queda vacía) y registro de niveles de certeza (`HIGH`, `MEDIUM`, `LOW`, `NOT_FOUND`).
  - Manejo de reintentos y captura de errores en `lead_extractions`.
  - Pruebas automatizadas unitarias con mocks para escenarios de timeout, cuota agotada y error de formato.
  - **Prueba empírica obligatoria con Gemini API real y una solicitud sintética nueva** como criterio indispensable de aceptación y cierre (en espera de credencial local).
- **Excluye:** Interfaz visual compleja de triage (TP-03), gestión de próximas acciones (TP-04), preparación de demo (TP-05).

- **Requisitos cubiertos:** `MVP-02` (Ingreso funcional), `MVP-03` (Persistencia e idempotencia), `MVP-04` (IA real), `MVP-05` (Evidencia y límites), `MVP-11` (Continuidad ante fallos).

  - Si la empresa no está en el texto, el campo permanece vacío y no se inventa.
  - Un fallo de cuota o timeout se captura registrando el error sin bloquear el servidor.
